# Reconciling a pre-existing local TEOS installation

**Source of truth for shared Skills**: this public repository, `Trigenys/trigenys-engineering-os`. **Source of truth for formal RAIDER**: `EagleFox31/project-registry/RAIDER.md` at the documented upstream SHA. **Source of truth for local customizations**: the user's machine until the user approves an explicit migration.

## Why reconciliation is needed

A separate Cursor Agent installed **28 Skills** in `~/.cursor/skills`, **15 Cursor agents**, **8 Python scripts**, `teos.ps1` and two adapter Skills in the local user profile on 2026-10-09, before this repository was the reference. The repository contains **44 canonical Skills** and **19 agent profiles**.

## Observed comparison (2026-10-09, Windows machine, repo `be00440`)

`compare-local` on the machine reported, with no file modified: 0 identical, 38 different (28 Skills + 10 agents), 112 missing, plus local-only items. The 38 differing files were generated by the local installer the same day and contain no user customization, so replacing them loses nothing beyond the backups.

Name mismatches found:

| Local agent | Repository agent |
|---|---|
| `devsecops-security-architect.md` | `devsecops-architect.md` |
| `senior-project-manager.md` | `project-manager.md` |
| `principal-qa-automation-engineer.md` | `qa-automation-engineer.md` |
| `ux-ui-cx-strategist.md` | `ux-cx-strategist.md` |
| `implementation-engineer.md` | added to the repository in this sync |

The installer never deletes, so a renamed local agent keeps loading next to its replacement. `compare-local` now reports these as `SUPERSEDED`, and TEOS Skills left in a folder the current `--tools` selection no longer uses as `REDUNDANT`. Both must be removed by hand after review.

## Read-only reconciliation

Use `python` if the `py` launcher is not installed.

```powershell
git clone https://github.com/Trigenys/trigenys-engineering-os.git
cd trigenys-engineering-os
py scripts/install.py check
py scripts/install.py compare-local
py scripts/install.py install-global --dry-run
```

## Applying updates safely

Only after reviewing the report:

1. Back up and remove the `SUPERSEDED` agents and the `REDUNDANT` Skill folders listed by `compare-local` (for the machine above: the 28 TEOS Skills in `~/.cursor/skills` and the 4 renamed agents).
2. Run:

```powershell
py scripts/install.py install-global --dry-run --update
py scripts/install.py install-global --update
py scripts/install.py compare-local --strict
```

- Identical content is an idempotent no-op.
- Differing paths are moved to `~/.teos-backups/<UTC-stamp>/` before replacement, never next to the original.
- Non-TEOS local user skills and agents are never deleted.
- Existing `$HOME/.cursor/trigenys-engineering-os/` scripts are left untouched.
- Project application repositories are never modified by global installation.
- User Rules and runtime model selection remain manual/independently verifiable.

## Local-only additions

The eleven local Python scripts and `teos.ps1` in `~/.cursor/trigenys-engineering-os/scripts/` were audited in [`docs/audits/2026-10-09-local-scripts-audit.md`](../audits/2026-10-09-local-scripts-audit.md). Their useful checks now live in `scripts/teos_checks.py`, with tests; the rest is superseded. Keep them until the audit is accepted, then archive them rather than delete.

## Acceptance checks

- Confirm the Cursor Skills catalog and subagents after restarting an Agent session; check that each TEOS Skill appears once per name. On Cursor 3.21.16 the agent-visible Skill list showed one entry per name, but the winning copy was not predictable; the Skills UI check is tracked in [#7](https://github.com/Trigenys/trigenys-engineering-os/issues/7). The list of a running window is not refreshed when folders are removed: reload the window first.
- Confirm actual subagent model execution in the agent run details, rather than trusting YAML alone.
- Validate cross-tool adapters separately in Cursor, Claude Code and Codex. Their profile/state is not shared.
